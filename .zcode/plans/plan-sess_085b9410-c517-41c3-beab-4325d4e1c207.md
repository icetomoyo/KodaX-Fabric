# 重design「新增渠道」表单并打通自建渠道的 Key 测试链路

## 背景与目标

当前新增渠道表单的核心缺陷：**自建渠道（海致）缺少"测试模型"配置**，导致员工「测试+提交渠道 KEY」必然报 400「无法确定测试模型」（`resolveUpstreamTestModel` 只为 glm/deepseek 内置默认模型）。另有一批表单不合理细节一并修复。

## 一、新表单设计（最终形态）

**供应商 + 线路**（保留）：智谱（国内/国际）、DeepSeek、海致集团（自建）。

**ChannelConfigFields 内**（按供应商联动）：
| 字段 | 变化 |
|---|---|
| 渠道名称 / 标签 / 席位数量 | 保留不变 |
| 渠道状态 | **新建时不再显示**（新渠道一律启用，后端已默认 active）；编辑时保留。组件加 `showStatus` prop |
| API 协议 | 默认值从"全勾三种"改为按供应商：glm→三种全选，deepseek/haizhi→仅 openai_chat；**切换供应商时同步重置**（修复现状只重置 URL 不重置协议的 bug） |
| 上游地址 | 保留（仅自建显示） |
| **测试模型（新增）** | 仅自建渠道显示，el-input，≤128 字符，帮助文案"员工提交 KEY 做连通性测试时使用的模型名，如 glm-4.5-air"。新建/编辑共用 |

## 二、后端改动

1. **迁移 0054**：`product_lines` 加列 `test_model varchar(128)`（可空）；同步 `server/src/db/schema/index.ts` 加 `testModel` 字段、`meta/_journal.json` 加条目。
2. **创建**（`upstream-channel-create.ts` + `providers.ts` POST）：plan 接受可选 `testModel`（trim 后 1-128，空/缺省→null，超长→新错误 `test_model_invalid`），插入时落库；`channelCreateError` 补错误文案。
3. **测试模型解析链**（优先级：渠道 testModel > 凭证 discoveredModels > glm/deepseek 内置默认）：
   - `me.ts:487` 员工测试端点：`probeUpstreamModels({ ..., model: located.productLine.testModel ?? undefined })` —— 库函数已支持 `input.model` 优先，只需传参。
   - `admin/credentials.ts testCredentialConnection`：同样在 probe 前查 productLine.testModel 并传入（管理员显式配置优先于历史发现）。
4. **编辑**（`upstream-channel-update.ts` schema + `providers.ts` PATCH）：允许更新 `testModel`（可清空）；**不** bump configVersion、**不**重置凭证健康（不影响转发语义）。
5. GET /api/admin/product-lines 为 `select` 整行，testModel 自动返回，前端可直接读。

## 三、前端改动（CredentialsView.vue + ChannelConfigFields.vue）

- ChannelConfigFields：加 `testModel` defineModel + 测试模型输入框（`v-if="editable"`）；加 `showStatus` prop 控制状态字段。
- CredentialsView：
  - `createForm.testModel`、resetCreateForm 重置；saveChannelCreate 在 haizhi 时携带 `testModel`（trim 后空串不发）。
  - provider/variant 切换 watch：重置 `supportedProtocols` 为该供应商默认 + 清空 testModel（保留现有 protocolConfigs 重置）。
  - 编辑表单：`channelEditForm.testModel` 从渠道数据初始化，saveChannelEdit 的 PATCH 携带（仅自建渠道）。

## 四、E2E 更新（唯一验证手段，产出可重复报告）

`e2e/core-relay.spec.ts`：
1. **修复团队创建**（上个提交删除了 POST /api/admin/teams）：创建企业（自动建默认部门+默认团队）→ `GET /api/admin/teams?enterpriseId=` 定位默认团队 → 仍用保留的 `POST /api/admin/teams/:id/members` 邀请员工。
2. 渠道创建携带 `testModel: "e2e-upstream-model"`。
3. **恢复员工提交链路**（本功能的主验证）：管理员建席位 → 员工 test（此时有 testModel 可解析）→ proof → submit → 创建 API Key → relay 调用 → 员工/管理员日志页可见。替代现在的管理员 bulk-create 导入路径。

## 五、顺带同步
