## 1. 产品与范围

### 1.1 一句话

Token Hub 是 Fabric 的核心模块：公司内网 **LLM 统一网关 + 官方凭证池调度 + 员工级调用审计**。员工只持有内部 API Key（`th_...`），上游官方凭证由管理员集中托管。

### 1.2 公测要达成什么

- 公司内部员工可按流程开通账号、自助创建 Key、用 **Claude Code / Cursor**（双协议）调用模型  
- 管理员可配置渠道与凭证、查阅调用与工单、执行发布与备份托底  
- 公测硬门槛 **E1～E10** 有成文证据，可签字「允许扩大使用」（见附录 A）

### 1.3 明确不做（0.1.0 / 本公测阶段）

| 不做 | 说明 |
|------|------|
| 对外公开注册 / API 售卖 | 仅公司内部账号 |
| 充值、余额、倍率计费 | 只做用量治理（日 Token 硬上限） |
| Token ROI / 浪费分析 / 文件归因 | Fabric 后续模块 |
| 组织多级预算 / Commerce | 不在 Token Hub 公测范围 |
| SSO / OIDC | 后续能力 |
| 跨渠道容灾、协议互转 | Key 绑定渠道 + 协议，原生透传 |
| 网页聊天 Playground | 入口为 IDE / CLI / 脚本 |

## 2. 角色与入口

| 角色 | 页面 | 职责摘要 |
|------|------|----------|
| **管理员** `admin` | `/admin/*` | 员工与审核、渠道/凭证、配额、全量日志、工单、操作审计、概览 |
| **员工** `employee` | `/me/*` | 改密、创建/删除自己的 Key、个人用量与日志、提交/查看自己的工单 |
| **调用方** | `/ai/*` | 仅 API Key，无页面权限 |

规则：

- 管理端与员工端 **无切换入口**；角色隔离严格执行  
- `admin` **不能**创建调用 Key，也不能进入员工端业务  
- 用户从 `employee` 变为 `admin` 时，其全部 active 调用 Key 在同一事务内 **revoke**  
- 生产访问：`https://tokenhub.haizhi.com`（公网受信任证书；保持客户端 TLS 校验开启）

## 3. 账号生命周期 {#e4-account}

### 3.1 开户方式（公测默认）

以下两种 **均可**，公测阶段并行：

| 方式 | 流程 | 说明 |
|------|------|------|
| **A. 注册申请 + 审核** | 登录页提交姓名、部门、手机号 → 待审核 → 管理员在「员工管理」通过 | 通过后初始密码固定为 `Hz@123456`，**必须强制改密**后方可使用业务 |
| **B. 管理员创建/批量导入** | 管理员直接创建员工并设定初始密码与角色 | 同样要求首次/重置后强制改密 |

- 登录标识：**手机号唯一**  
- 待审核账号：**不能登录、不能调用模型**  
- 停用账号：不能登录；其名下调用 Key **不能**通过代理鉴权  

### 3.2 停用与离职

| 场景 | 管理员动作 | 预期结果 |
|------|------------|----------|
| 临时停用 | 将员工状态设为停用 | 无法登录；Key 鉴权失败 |
| 离职 / 长期不用 | 停用账号；如需可删除其员工 Key（员工端删除或等效运维） | 调用立即不可用 |
| 角色调为 admin | 系统 revoke 全部 active 调用 Key | 不可再作为 employee 调用方 |

**责任人**：日常审核与启停由 **Token Hub 管理员**（见 §8）执行；人事侧离职名单应知会管理员，避免账号滞留。

### 3.3 密码

- 首次登录 / 管理员重置后：`must_change_password = true`，改密前不能使用业务页与模型代理  
- 管理员可重置密码；用户下次登录必须改密

## 4. 渠道与凭证策略 {#e3-channel}

### 4.1 概念（与实现对齐）

```text
Provider（供应商）
  └─ ProductLine（上游渠道：api | coding_plan）
       └─ UpstreamCredential（加密上游 Key，可多条）
```

- 员工 API Key **硬绑定** 一个 `ProductLine` + 一种协议  
- 模型列表、解析、选凭证、重试 **均不得跨渠道**  
- 共享模式：  
  - `public_pool`：active 员工可使用渠道内符合条件的凭证  
  - `grant_only`：仅被授权员工可使用指定凭证（典型：Coding Plan）  

### 4.2 公测默认策略（配置基线）

| 规则 | 公测基线 |
|------|----------|
| **优先开放** | 公司已采购、条款清晰的 **官方 API** 渠道（`productType = api`，`share_mode = public_pool`） |
| **Coding Plan / 套餐类** | 默认 **`grant_only`**；**不得**对全员默认 public_pool 混用 |
| **grant_only 授权** | 仅管理员按名单授予；撤销后下次请求立即不可用 |
| **新渠道上线** | 管理员完成连接测试与（按需）模型发现后，再对公测员工可见 |
| **扩大渠道** | 先单供应商/单渠道验证，再扩展；避免一次打开全部采购凭证 |

> 管理员在管理端实际勾选的「启用」状态以系统配置为准；**本文约束「该开什么、不该怎么开」**。若现网已临时放宽，扩大公测前须回到本表或书面修订本表。

### 4.3 协议

| 协议 | 典型客户端 | 代理入口（相对 Base URL） |
|------|------------|---------------------------|
| `anthropic_messages` | Claude Code 等 | Messages：`/ai/v1/messages` 等 |
| `openai_chat` | Cursor / OpenAI 兼容客户端 | Chat Completions：`/ai/chat/completions` |

- **一种客户端建议一把员工 Key**（创建时选对应协议）  
- **不做** Chat Completions ↔ Messages 协议互转  

### 4.4 员工 Key 安全（摘要）

- 明文 **仅创建成功时向创建员工本人展示一次**；关闭后不可再读  
- 管理员 **不能** 列表/查看/复制员工 Key 明文  
- 泄漏：员工删除旧 Key 并重建；管理员配合停用账号

## 5. 配额与限流 {#e5-quota}

### 5.1 业务配额（日 Token）

| 项 | 基线 |
|----|------|
| 主体 | **每名员工** 共用一个单日总 Token **硬上限** |
| 日界 | `QUOTA_TIMEZONE` 的 `00:00:00`（默认 **Asia/Shanghai**） |
| 打满行为 | **拒绝后续请求**（硬限，不软放行） |
| 种子默认值 | 空库种子 `dailyTokenLimit = 500_000_000`（5 亿 Token/日） |

**公测评审记录（E5 证据）：**

| 项 | 填写 |
|----|------|
| 是否沿用种子默认 5e8 | ☐ 沿用　☐ 调整为：________ |
| 评审人 | ________ |
| 日期 | ________ |
| 备注 | （例如按部门沟通后的值；在管理端「配额策略」落地） |

> 未填写评审前，**技术上**仍可能使用库内当前值；**扩大公测签字前必须完成本表**。

### 5.2 系统级 safeguard（非业务策略）

由环境变量固定（部署时配置），用于保护上游与网关，**不作**多套业务配额策略：

| 项 | 配置键（默认量级见服务端 config） |
|----|-----------------------------------|
| 每员工 RPM | `RELAY_SAFEGUARD_RPM`（默认 60） |
| 每员工并发 | `RELAY_SAFEGUARD_MAX_CONCURRENCY`（默认 5） |

员工侧若频繁 429，先查是否触达日 Token 或 safeguard，再查上游冷却。

## 6. 安全底线 {#e8-security}

| 要求 | 说明 |
|------|------|
| 使用范围 | **仅公司内部**账号与用途；禁止对外转售或给外部方共享员工 Key |
| 传输 | 生产使用 HTTPS（`tokenhub.haizhi.com` 公网受信任证书） |
| 上游 Secret | 仅管理员维护，加密存储；界面不回显完整 Secret；不出现在员工接口与审计不当字段 |
| 员工 Key | 哈希鉴权；明文一次性；不进截图/工单正文/仓库 |
| 审计正文 | 经脱敏与容量限制；管理员查阅他人正文应有操作审计意识 |
| 管理账号 | 管理员密码足够强；不把 `SEED_ADMIN_*` 长期写在运行 `.env`（见 deploy 说明） |
| 证书私钥 | 仅主机受控路径；不进镜像、不进 Git、不进日志 |

## 7. 接入与客户端（员工） {#e9-onboarding}

详细步骤以员工端 **`/me/guide` 接入教程** 为准（含可复制配置片段）。章程级约定：

1. 浏览器打开 `https://tokenhub.haizhi.com`，确认 HTTPS 正常（可打开健康检查）  
2. 登录并完成强制改密  
3. 在 **API Key** 页：选上游渠道 → 选协议 → 命名 → 创建 → **立即保存明文**  
4. 在 Claude Code / Cursor 中配置 Base URL 与 Key（协议与客户端一致）  
5. 调用后可在 **我的调用** 查看记录；问题走 §8  

| 客户端 | Key 协议 | 配置要点 |
|--------|----------|----------|
| Claude Code | `anthropic_messages` | `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`（见教程） |
| Cursor | `openai_chat` | OpenAI Base URL + API Key / `OPENAI_*` 环境变量 |
| 其他 OpenAI 兼容 | `openai_chat` | 同上 |

**一种客户端一把 Key**；不要把 Anthropic Key 配进 Cursor，或把 Chat Completions Key 配进 Claude Code。
