## 最终决策

TokenHub 尚未部署，也没有外部客户端依赖历史管理接口，因此 v0.0.3 不设置接口或数据模型兼容期。实现直接发布目标契约：

- 日志元数据：`GET /api/admin/logs/:requestId`。
- 管理员结构化上下文：`GET /api/admin/logs/:requestId/context`。
- 单一配额：`GET/PUT /api/admin/quota-policy`。
- 配额数据只使用 `quota_policy.daily_token_limit`；不存在多策略和员工覆盖。

## 已确认口径

- `summary` 与 `daily` 的 Token、请求数和失败数统一来自 `usage_counters_daily`，保持强一致。
- Provider/Model 分布来自 `request_audits`，缺失 usage 通过 `unknownUsageCount` 提示。
- 配额与员工详情按 `QUOTA_TIMEZONE` 解释自然日，`dailyTokenLimit=0` 合法且拒绝全部调用。
- `remainingToday = max(0, dailyTokenLimit - usedToday)`。
- `log.read_context` 按 actor + Request ID 在五分钟内去重。
- 渠道汇总使用滚动 24 小时，渠道详情与 Key 列表职责分离。

## 数据库收敛

开发库 Migration 将临时开发阶段的数据结构收敛为首次发布结构：

- 建立单行 `quota_policy`，保留已有非空硬限，空值使用 500000000。
- 删除多策略、员工覆盖、软限、日请求限等无效结构。
- 删除日用量中的软限命中字段。

该迁移只服务本地开发库升级，不构成对外兼容承诺。

## 必测项

- 管理员上下文权限与敏感字段脱敏。
- 员工用量聚合强一致、空日期补零及 366 天边界。
- 单日 Token 硬限、零额度和时区午夜边界。
- 渠道汇总、Key 列表分层及 Secret 防泄漏。
- 数据库迁移、服务端测试、API 集成测试和前后端生产构建。
