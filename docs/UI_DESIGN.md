# KodaX Fabric — UI 设计草稿（ASCII Wireframes）

> 本文档用 ASCII 线框图描述 Fabric 管理控制台各个界面的草稿，帮助直观理解每个界面体现的功能点。
>
> **现行落地（v0.1.3）**：三角色共用 `/admin` 壳，按角色裁侧栏。没有超管、没有 17 个独立大屏。下文线框是愿景。
>
> **布局约定**：所有界面共享顶部导航栏 + 左侧子导航。
>
> **部署模式说明**：
> - **SaaS/平台部署**：全部 17 个界面，超管管理 Commerce（12-14），企业管理员管理本企业配置
> - **单一企业 + 外部 API**：全部 17 个界面，企业管理员管理全部（含 Commerce 12-14，内部定价/内部预算/内部团队账单）
> - **单一企业 + 仅自建模型**：14 个界面（1-11 + 15-17），无 Commerce 界面（12-14）。配额由预算管理（5）覆盖，用量由用量分析（7）覆盖，无超管角色

## 角色权限矩阵

> Fabric 管理控制台有四种角色，每种角色看到不同的界面和数据范围。同一界面对不同角色显示不同范围的数据。

### 角色定义

| 角色 | 定位 | 典型用户 |
|---|---|---|
| **超管**（平台运营） | 管理 Fabric 平台本身，面向所有客户 | KodaX 平台运营团队 |
| **企业管理员** | 管理本企业的 Fabric 配置 | 企业 IT / 平台团队负责人 |
| **团队管理员** | 管理本团队的项目和 Virtual Key | 团队 Tech Lead |
| **开发者** | 使用 Virtual Key 开发应用 | 开发工程师 |

> **超管角色仅在 SaaS/平台模式下存在。** 单一企业的最高角色是企业管理员。使用外部 API 时管理全部 17 个界面（含 Commerce 12-14）；仅自建模型时管理 14 个界面（无 Commerce 12-14）。SaaS/平台部署中，Commerce 界面由超管管理，企业管理员不可见。

### 数据范围收敛

```text
超管:       所有客户 > 所有企业 > 所有团队 > 所有项目
企业管理员:           本企业 > 所有团队 > 所有项目
团队管理员:                     本团队 > 本团队的项目
开发者:                                   自己的 VK 关联的项目
```

> 数据范围通过 Virtual Key → Project → Team 链路自动过滤。角色权限通过 RBAC 策略控制，不需要每个界面单独实现。
>
> **Commerce 界面（12-14）的适用场景**：
> - SaaS/平台模式：由超管管理，完整商业功能（Credits/split/markup/三层计量/利润追踪）
> - 单一企业 + 外部 API：由企业管理员管理，功能简化（内部定价/内部预算套餐/内部成本报告，无三层利润分解）
> - 单一企业 + 仅自建模型：不显示。配额由预算管理（5）覆盖，用量由用量分析（7）覆盖
>
> **导航可见性**：“定价与计费”导航入口不由部署模式硬编码，而是由角色权限 + 是否配置了外部 API Provider 共同决定。超管（SaaS）或企业管理员（单一企业+外部API）可见；仅自建模型时不显示。
