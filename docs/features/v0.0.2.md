## FEATURE_002: 上游钥匙柜

> **状态**：**Completed**  
> **回填**：按现网综合  
> **版本**：v0.0.2 → Released v0.1.0

来源：切片 0.0.2 · VISION #10 #12 #13 #14 · HLD §3.4 / 加密选型 AES-256-GCM

### 1. 需求概述

#### Problem Statement

管理员要把公司买来的官方 Key 放进网关，员工页面永远不能看见明文。同一家常有多把 Key，废了的必须能摘掉。

#### Solution

`providers` + `provider_keys`。创建时 `secret.Encrypt`（AES-GCM）写入 `secret_encrypted`。列表接口只回 `id / provider_code / label / status`，不回密文。`ResolveVK` 只 join `pk.status = 'active'`，解密后填进渠的 `Secret` 打上游。

#### Out of Scope

- 自动轮换、401 自动停用、Key 级 RPM/模型表
- 员工可见官方 Key

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 存储 | `providers`、`provider_keys.secret_encrypted` |
| 管理 API | `GET/POST /api/v1/providers`、`GET/POST /api/v1/provider-keys`、`POST /api/v1/provider-keys/{id}/status` |
| 热路径 | 不改端点；选路时解密 Key 写入上游 Authorization / x-api-key |
| UI | `/admin` 编目（0.1.0 操作台） |

### 3. 技术方案

- 加密：`CREDENTIAL_ENCRYPT_KEY` 32 字节或 64 hex → AES-256-GCM。
- 多 Key：同一 `provider_code` 多行；摊流量靠多条 `channels` 各绑一把 Key，不是运行时在 Key 表里抽签。
- 停用：`status` ≠ `active` 则该 Key 下的渠不会被解析出来。
- 列表永不返回明文或密文。

### 4. 接口契约

| 方法 | 路径 | 角色 | 行为 |
|------|------|------|------|
| POST | `/api/v1/provider-keys` | admin | body：`provider_code, label, secret, status`；入库加密 |
| GET | `/api/v1/provider-keys` | admin | 无 secret 字段 |
| POST | `/api/v1/provider-keys/{id}/status` | admin | `{ "status": "disabled" }` 后不再被选 |

调用方 `/v1/*` 仍只带 `fab-` VK。

|----|----------|------|

### 6. 验收标准

1. 管理员录入官方 Key 后，库内不是明文。
2. 列表/页面看不到官方 Key。
3. 同一 Provider 可挂多把 Key，各绑一条渠。
4. 把 Key 标停用后，新请求不再打这条渠。
5. 不要求 401 自动摘除或定时轮换。
