### 1. 需求概述

#### Problem Statement

同样一句「把这句话译成英文」每次都打上游，又贵又慢。流式回答不该被拿去复读。钥匙现在多半是管理员直接发，缺少「开发者申请、管理员点头」；漏到外面的 `fab-` 也没有来源 IP 限制。官方 Key 到期换新时，不该让员工改 Base URL 或停对话。

#### Solution

**响应缓存**只对标明可缓存的确定性非流请求生效：相同协议+模型+请求体命中则 200、0 次上游，并带头说明命中。默认不缓存。`stream:true` 永不缓存（#57）。厂家 prompt cache 字段照旧透传，不拦截（#50）。

**运营面**：VK 可处于待审批，未批不能调 `/v1`；审批后明文只亮一次。VK 可配 IP 白名单，不在名单则拒、0 上游。官方 Key 轮换：停旧钥、池里改挂新钥，员工 `fab-` 不变。

#### Out of Scope

- 0.1.0 镜像/备份/双端验收收口
- 四角色 SaaS 大控制台、完整审批工单 UI
- Redis 作为测试断言；命中率图表后台
- Token ROI / Commerce / SSO
- 排队、降级换便宜模型

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 响应缓存 | 仅非流 + 请求标明可缓存（头 `X-Fabric-Cacheable: true` 或 body `fabric_context.cacheable`）。键 = 协议 + model + 规范化 body。命中头 `X-Fabric-Cache: hit`，未中 `miss` |
| Prompt cache | 零转换：不删厂家 `cache_control` 等字段。本版不自建 prompt 缓存层 |
| 流式 | `stream:true` 不读、不写响应缓存 |
| VK 状态 | 增加 `pending`（及审批拒绝后不可用）。仅 `active` 能过 `/v1`。现有直接发放仍可立刻 active |
| IP | VK 可选白名单。空 = 不限。比对 `RemoteAddr`（可认第一段 `X-Forwarded-For`）。不匹配 → 403，上游 0 |
| 轮换 | 沿用 002 停用 + 渠改挂新 `provider_key`。员工 VK 不换 |
| 热路径 | 鉴权/隔离/过期/名单/限流/预算之后，打上游之前：IP → 缓存查找；命中则不再选渠 |
| 测试 | **只测 T1**（用户已确认）。夹具写 Store。不测登录页、不读 Redis/库当断言 |

### 3. 技术方案

**D1 默不缓存**  
没有可缓存标记的请求与现在一样，每次打上游。避免把普通对话复读成同一句。

**D2 命中短路**  
可缓存且非流：查缓存，命中则回上一份状态/body，假上游 0，头 `X-Fabric-Cache: hit`。未中打上游，2xx 则写入（TTL 夹具可配，默认足够测第二次命中）。

**D3 流式不进缓存**  
`stream:true` 跳过查找与写入。两次长流都打假上游。

**D4 待审批不可调**  
`status=pending`（或非 active）的 VK：`/v1` 401/约定拒绝，上游 0。申请接口写出 pending、无明文；审批后变 active 并返回一次明文。

**D5 IP 白名单**  
名单非空且来源不匹配 → 403，不打上游、不走缓存写入。空名单不拦。

**D6 轮换不换 fab-**  
停掉旧官方 Key 后，同池仍 active 的渠/新 Key 承接。调用方仍用同一把 `fab-`。

**D7 顺序**  
005 隔离 → 003 过期/名单 → 006 限流 → 007 预算 → **IP** → **响应缓存** → 004 选渠。缓存命中不算一次 RPM/预算消耗（未打上游）。

---

### 4. 接口契约

调用方路径不变。运营面在现有 `/console/v1` 上补申请/审批（或等价），不新开调用方端点。

| 条件 | 行为 |
|------|------|
| 可缓存非流，第二次相同请求 | 200，上游命中 0，`X-Fabric-Cache: hit` |
| 默认可缓存关 | 每次都打上游 |
| `stream:true` 两次 | 上游 2 次，无 hit |
| VK `pending` | `/v1` 拒绝，上游 0 |
| IP 不在白名单 | 403，上游 0 |
| 白名单为空 | 不因 IP 拒绝 |
| 旧官方 Key 已停、新 Key 在池 | 同一 `fab-` 打到新钥上游 |
| 官方 Key 明文 | 仍不得出现在调用方 `/v1` 响应 |

### 6. 验收标准

#### User Stories

1. 作为平台，确定性重复问题应打中缓存，少烧上游。  
2. 作为开发者，流式回答不应被拿去当下次复读。  
3. 作为开发者，我申请的钥匙未批准前不能调。  
4. 作为平台，漏出的 VK 若限制了 IP，外面调不成。  
5. 作为平台，换官方 Key 时员工不用换 `fab-`。  
6. 作为开发者，厂家 prompt cache 字段不被网关丢掉。  
7. 作为开发者，没开缓存、没设白名单的旧钥匙行为不变。
