## FEATURE_008: 申请审批、一次性 reveal、IP 白名单

> **状态**：**Completed**（运营面）；缓存与自动轮换标缺口  
> **版本**：v0.0.8 → Released v0.1.0

### 1. 需求概述

#### Problem Statement

不能靠管理员私下发官方 Key。开发者申请、管理员批、明文只亮一次。泄漏的钥匙应能限制来源或吊销。

#### Solution

`vk_applications`：pending → approve 时创建 VK，明文暂存 `raw_key_once`。开发者 `reveal` 读走后清空。`ip_whitelist` 逗号分隔，热路径 `ipAllowed`。`revoke` 把 VK `status=revoked`，之后解析当不存在。

#### Out of Scope

- 响应缓存、Prompt 缓存运营、自动轮换
- 四角色；现网审批人是任意 `admin`

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 数据 | `vk_applications`、`virtual_keys.ip_whitelist` |
| API | `/api/v1/me/vk-applications*`、`/api/v1/vk-applications/{id}/approve`、`/virtual-keys/{id}/revoke` |
| UI | `/me` 申请与 reveal；`/admin` 审批 |
| 热路径 | IP 检查在 RPM/预算之前 |

### 3. 技术方案

- Cookie 会话 `th_session`；`GET /api/v1/auth/me` 无会话 200 + `data: null`。
- reveal 第二次 → 错（`key already revealed`）。
- 客户端 IP：`X-Forwarded-For` 第一段，否则 `RemoteAddr`。`*` 放行。

### 4. 接口契约

| 方法 | 路径 | 角色 |
|------|------|------|
| POST | `/api/v1/me/vk-applications` | developer |
| GET | `/api/v1/me/vk-applications` | developer |
| POST | `/api/v1/me/vk-applications/{id}/reveal` | developer |
| GET | `/api/v1/vk-applications` | admin |
| POST | `/api/v1/vk-applications/{id}/approve` | admin |
| POST | `/api/v1/virtual-keys/{id}/revoke` | admin |

IP 拒绝：403 `ip not allowed`。

### 6. 验收标准

1. 开发者申请后看不到明文，批准并 reveal 一次后能拷到 `fab-`。
2. 再 reveal 失败。
3. 配了 IP 白名单，非名单来源 403。
4. 吊销后该 VK 401。
5. 不验收响应缓存命中、官方 Key 自动轮换。
