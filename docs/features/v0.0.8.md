## FEATURE_008: 运营闸与缓存

> **状态**：**Completed**
> **版本**：v0.0.8 → Released v0.0.8

### 1. 需求概述

非白名单 IP 在路由/预算/上游前 403。pending/rejected 申请没有可调用 VK。approve 事务化生成 `fab-`，库中只留 hash/前缀/masked。轮换宽限期新旧 secret 重叠，到期旧 secret 退出。确定性响应可缓存，命中零上游且不耗限流/预算。

### 2. 影响范围

`ResolvedVK.IPAllow`；`vk_applications`；`provider_keys.replacement_*`；`ResponseCache`；`GET /health/cache`；`/admin/v1/*`。管理认证：`ADMIN_TOKEN` 常量时间比较，缺 token fail-closed。

### 3. 技术方案

- IP：先校验全部规则，任一非法 fail-closed；只信 `RemoteAddr`。
- 审批：`subtle`+SHA256 比较管理 token；`Approve` 二次调用 `409` 且不再回明文。
- 轮换：激活后新凭据首选，宽限期旧凭据仅 401/403 auth fallback；完成后 stage 先晋升再写下一把；`CACHE_TTL`/`retire` 校验。
- 响应缓存只在完整读+完整写成功后 Set；回放仅 `Content-Type`。TTL 由 `CACHE_TTL`（默认 1h，非法启动失败）。
- Prompt：OpenAI `cached_tokens` 与 Anthropic `cache_read` 才算命中节省；Anthropic 无 total 时 input+output+create+read。

### 4. 接口契约

- `403` `ip_not_allowed`
- `X-Fabric-Cache: HIT|MISS|BYPASS`
- `GET /health/cache` candidates/hits/misses/writes/tokens_saved
- `POST /admin/v1/vk-applications`…`/approve|/reject`
- `POST /admin/v1/provider-keys/{id}/rotate` + `/activate`

### 5–6. 实现与验收

T1：IP 允许/拒绝/伪造头/非法配置；缓存命中零上游、默认关、TTL、租户隔离、错误不存、协议不串、SSE 双上游+prompt 字段不变、命中仍受 IP/模型约束；审批明文一次；轮换 overlap/retire。
