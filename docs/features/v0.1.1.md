### 1. 需求概述

#### Problem Statement

0.1.0 按切法六条收口后，回归仍有五条不能当生产看：白名单可被伪造 XFF 绕过；发布镜像嵌的是旧前端；模型别名与 Provider RPM 只在 T1 夹具里通；restore 会重跑 bootstrap 改写刚还原的库；Redis 挂了 `/health` 仍 200。

#### Solution

五条全部修进网关 / compose / 镜像，打成补丁版 v0.1.1。不另开产品能力，不改调用方 `/v1` 路径。

#### Out of Scope

- 控制台体验、三角色、四角色 SaaS
- Embedding / Batch / Token ROI
- DeepSeek 官方 401（凭据问题，不入库）

### 3. 技术方案

**ISSUE_001**  
默认不用客户端可写的 `X-Forwarded-For`。反代部署显式 `TRUST_PROXY=1`。

**ISSUE_002**  
`//go:embed` 吃到的必须是当前 `web/src` 编出来的 dist。构建门禁放在 Dockerfile，不靠人手提交 dist。

**ISSUE_003**  
别名与 Provider RPM 从「仅夹具」改成生产接线：表、启动加载、`ResolveVK`、控制台读写。

**ISSUE_004**  
gateway `depends_on: bootstrap`。`compose start` 会连带拉起 bootstrap，且不支持 `--no-deps`。还原只 `up -d --no-deps gateway`。

**ISSUE_005**  
Redis 是 compose 硬依赖时，健康检查按依赖探活：`PING`，不是端口通。未配置 `REDIS_URL` 仍只看 Postgres。hub T1 `/health` 保持简单 200。

### 4. 接口契约

| 条件 | 行为 |
|------|------|
| VK 配了 IP 白名单，未设 `TRUST_PROXY`，请求带伪造 XFF | 403，上游 0 |
| 同上，`TRUST_PROXY=1`，XFF 第一段在名单内 | 按白名单放行 |
| 镜像构建 | 先编前端再 embed；`/admin` 侧栏含团队项目、路由审计 |
| `PUT/GET /console/v1/model-aliases` | 生产可配；网关启动后热路径用得到 |
| `PATCH` 官方 Key 的 `rpm_limit` | `ResolveVK` 带上，Provider 维 RPM 生效 |
| `./restore.sh` 之后 | 不重跑 bootstrap；dump 里的 operator / VK 不被种子覆盖 |
| `REDIS_URL` 已配且 Redis `PING` 失败 | `GET /health` 503，`ok: false`，`redis: false` |
| 未配 `REDIS_URL` | `/health` 仍只看 Postgres |

### 6. 验收标准

#### User Stories

1. 作为平台，直出 8080 时客户端不能靠伪造 `X-Forwarded-For` 绕过 VK IP 白名单。

3. 作为管理员，我能在控制台配置模型别名和官方 Key 的 RPM，生产网关会执行。  
4. 作为运维，还原备份后种子脚本不会改写刚灌进去的库。  
5. 作为运维，Redis 不可达时 `/health` 不是 200。
