## Part A — 版本级叙事

### 版本目标

对照 [token-hub-slices.md](../token-hub-slices.md) 六条独立部署标准勾选。0.0.2–0.0.8 能力在本收口一并交付。

### 六条标准（现网）

| # | 标准 | 现网 |
|---|------|------|
| 1 | Go 单进程；依赖 PG + Redis。ClickHouse / S3 / 计费不进 | 是。Redis 容器在，热状态仍是内存 |
| 2 | 双端点 + `fab-`；调用方碰不到 Provider Key | 是 |
| 3 | VK → Pool → Channel；同协议 failover；禁止硬绑单渠 | 是 |
| 4 | 限流 + 熔断 + VK 预算各一种硬拒绝 | 429 / 503 / 402 |
| 5 | 发布/回滚/备份、`/health`、管理员配 Provider/Channel/Pool/VK | compose + runbook + `/admin` |
| 6 | 同一把 VK 走通 Cursor 与 Claude Code | 两端点共用 VK |

**不做**：ROI、Commerce、ClickHouse、SSO、17 屏、聊天试玩、四角色。

## FEATURE_009: 0.1.0 独立部署收口

> **状态**：**Completed**  
> **版本**：v0.1.0 → Released v0.1.0  
> 仓库已有 git tag `v0.1.0`；本文件只补设计块，不代替再跑 smart-release。

### 1. 需求概述

#### Problem Statement

切片能力已经在一个 goal 里收口，但没有独立部署说明书和操作台，内部没法当过渡网关用。

#### Solution

单进程 gateway：热路径 `/v1/*`、管理 `/api/v1/*`、操作台 embed `/` `/admin` `/me`。compose 起 PG + Redis + bootstrap + gateway。runbook 写备份回滚。本机默认 API **3000**、操作台 **8080**。

#### Out of Scope

- K8s、ClickHouse、MinIO、Redis Cluster 真用起来
- 把 0.0.8 未做的缓存/自动轮换补进本版

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 进程 | `cmd/gateway` + `cmd/bootstrap` |
| 部署 | `deploy/compose.yaml`、`deploy/runbook.md`、`deploy/backup.sh` |
| UI | `web/` → `internal/webui/dist` embed |
| 健康 | `GET /health`：postgres / redis ping |

### 3. 技术方案

- 管理 API 扁平路径（不是 HLD `/providers/{id}/channels`）。UI 跟代码字段。
- bootstrap 要 `DEEPSEEK_API_KEY`；库已种过可用 `--no-deps gateway`。
- 角色只有 admin / developer。

### 4. 接口契约

对外 Origin = API 口（本机 `http://127.0.0.1:3000`），不要带 `/v1`。  
页面：`http://127.0.0.1:8080/`。  
`GET /health` → `{ ok, postgres, redis, service }`。

1. `curl /health` ok，PG 通。
2. 管理员能配 Provider / Key / Pool / Channel / VK。
3. 开发者能申请并一次性看到 `fab-`。

5. RPM / 预算 / 熔断至少各能硬拒一次。
6. 有备份脚本与回滚说明。
