### 1. 需求概述

#### Problem Statement

001–008 的能力已经在进程里跑通，但作为「可独立交付的模块」还不完整：Postgres 容器一删数据就没了；备份/回滚没有可跟的步骤；双端验收（Cursor + Claude Code 同一把 `fab-`）只在口头上成立。运维没法按清单勾选「这套东西能发布」。

#### Solution

**只收口、不加新能力。** 把现有单进程网关 + compose（Gateway / PostgreSQL / Redis）补成可发布形态：库数据有卷、能备份能还原、`/health` 能反映依赖、文档能对照切法 6 条标准走完双端验收。调用方路径与 001–008 行为不变。

#### Out of Scope

- Token ROI / Commerce / 多租户控制台全量（HLD §4–§6）
- ClickHouse / S3 / 计费引擎
- 把限流/缓存/预算迁到 Redis（Redis 只作为 HLD 依赖留在 compose，`/health` 可探测）
- 新的调用方 `/v1` 路径；四角色 SaaS 大控制台
- K8s / 多机 HA / 蓝绿编排
- 排队、降级换便宜模型、Embedding / Batch

### 2. 影响范围

| 区域 | 决策 |

### 3. 技术方案

**D1 不加能力**  
001–008 的路由、限流、熔断、预算、缓存、审批/IP 行为保持原样。本版只补部署资产与文档。

**D2 单进程 + 两依赖**  
compose 继续拉起 gateway + postgres + redis + 一次性 bootstrap。Redis 在栈里、`/health` 能探；不把进程内桶/缓存改写成 Redis。

**D3 库要活得过重建**  
Postgres 挂命名卷。备份 = dump 该库；还原 = 停写后灌回。文档写清命令与 compose 项目名（`tokenhub`）。

**D4 发布/回滚写在纸上**  
发布：构建当前镜像并 `compose up --build --wait`。回滚：使用上一发布镜像 tag 再 up；需要时先还原库备份。不引入独立编排器。

**D5 双端同一把钥匙**  
文档写明：同一 `fab-`，Cursor 走 Chat Completions，Claude Code 走 Messages。bootstrap 的本地 VK 可作为手测钥匙。

**D6 六条标准清单**  
模块文档就是对照切法 0.1.0 六条的验收清单，不另开产品说明书。

---

### 4. 接口契约

调用方与管理端路径均不新增。收口验的是「现有接口在 compose 上成立」。

| 条件 | 行为 |
|------|------|
| `GET /health`，Postgres 可达 | 200，`ok: true`，带 `postgres` / `redis` 字段 |
| `GET /health`，Postgres 不可达 | 非 200 |
| 同一把 `fab-` 调两个 `/v1` | 均能按既有协议转发；响应不含官方 Key 明文 |
| compose 项目 `tokenhub` `--wait` | gateway 健康，8080 可访问 |
| 容器重建（卷在） | 原 VK / 官方 Key 编目仍在 |
| 按文档还原一份 dump | 还原后同一把 `fab-` 仍能调 `/v1` |
| 未开的旧钥匙 / 未标缓存 | 001–008 行为不变 |

### 6. 验收标准

#### User Stories

1. 作为平台，我能用一份 compose 拉起网关 + PostgreSQL + Redis，进程是单个 Gateway。  
2. 作为调用方，我只拿一把 `fab-`，Cursor 与 Claude Code 分别走两个端点都能通。  
3. 作为调用方，我在 `/v1` 响应里看不到官方 Key。  
4. 作为平台，VK 仍走池再走渠，没有「一把调用方钥匙绑死一条渠」。  
5. 作为平台，限流 / 熔断 / 预算仍然各有一种硬拒绝（001–008 测例仍绿）。  
6. 作为运维，`/health` 能告诉我库在不在。  
7. 作为运维，我能备份库并还原，重建容器不丢卷上的数据。  
8. 作为运维，我能按文档发布和回滚，不靠口头步骤。  
9. 作为管理员，我仍能在控制台配官方 Key / 池 / 渠 / VK。

#### Testing Decisions

**缝 T1 + D1（已确认，2026-08-14 用户确认「是」）**

- **T1**：进程内 `POST /v1/chat/completions` 与 `POST /v1/messages`。本版以 **001–008 全绿** 证明没改坏能力。不新开调用方测例，除非收口改动碰到了旧契约。  
- **D1**：`docker compose -p tokenhub` 拉起后，`GET /health` 为 200；同一把 `fab-` 打通两个 `/v1`（可用 bootstrap 钥匙 + 假上游或已配上游）。

夹具：现有 Memory/T1 夹具不动。D1 用 compose 真栈，不断言 Redis/库内容。

测外部行为：

- `go test ./...` 全绿。  
- compose `--wait` 后 `/health` 200。  
- 同一 `fab-` 两个端点均非鉴权失败（有渠时能转发）。  
- 备份/还原与 6 条清单：手测勾选，不写成 T1 断言。

**不测**：登录页、读库/读 Redis 当断言、K8s、多机 HA、把缓存命中率当发布门禁。
