## FEATURE_003: 虚拟钥匙一把两端口

> **状态**：**Completed**  
> **Spec**：已综合（T1）

### 1. 需求概述

#### Problem Statement

员工不该持有官方 Key，也不该为 GPT 和 Claude 各领一把。试用钥匙要能到期；有的钥匙只能打白名单模型。

#### Solution

VK 不带协议字段。过期按 `expires_at` 401。模型白名单按请求 JSON 的 `model` 比对，不在名单 403，不打上游。空名单 = 不限。

#### Out of Scope

申请流、IP 白名单、组织树、`fabric_context`。

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 热路径 | `relay`：过期、模型范围 |
| 数据 | `virtual_keys.expires_at`、`model_scope` |
| 测试 | T1，假上游 |

### 3. 技术方案

- 过期：`ExpiresAt != nil && !now.Before(*ExpiresAt)` → 401，与无效 VK 同 envelope。
- 模型：`model_scope` 逗号分隔；空不限；名单非空时必须先解析 body，再选渠。`model` 为空或不在名单 → 403 `model_not_allowed`，不推进轮转。
- 两端点共用同一把 VK（001 形状，本版验收）。

### 4. 接口契约

- 过期 / 无效：401 `invalid virtual key`
- 模型不在名单：403 `model not allowed`
- 调用方仍只持 `fab-`

### 6. 验收标准

1. 同一把 `fab-` 打 Chat Completions 与 Messages 都能通（池内两协议各有渠）。
2. `expires_at` 已过 → 401，上游 0 次。
3. `model` 不在 `model_scope` → 403，上游 0 次；在名单则 200。名单非空但缺少 `model`（或 JSON 无此字段）→ 403，上游 0 次。
