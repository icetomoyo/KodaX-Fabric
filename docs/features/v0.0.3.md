## FEATURE_003: 虚拟钥匙一把两端口

> **状态**：**Completed**  
> **版本**：v0.0.3 → Released v0.1.0

### 1. 需求概述

#### Problem Statement

员工不该持有官方 Key。也不该为 GPT 和 Claude 各领一把钥匙。试用钥匙要能到期；实习生钥匙要能限模型。

#### Solution

VK 明文一次性给出（管理员创建或开发者 reveal）。库里只留 `key_hash` + `key_prefix`。热路径：无 `fab-` / 未知 / 非 active / 过期 → 401（该协议 envelope）。`model` 不在 `model_scope` → 403。

#### Out of Scope

- `x-fabric-context` 业务语义
- 申请流、IP 白名单（0.0.8）

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 热路径 | `hub.relay`：前缀、过期、模型范围 |
| 数据 | `virtual_keys.expires_at`、`model_scope` |
| 管理 | `POST /api/v1/virtual-keys` 返回一次性 `virtual_key` |

### 3. 技术方案

- `secret.HashVK` = SHA-256 hex。
- 端点绑协议，VK 不绑协议（延续 0.0.1 D2）。
- `model_scope` 为逗号分隔字符串，空 = 不限。
- 过期用 `expires_at`；创建 API 现网未暴露设到期字段（库列在，种子/SQL 可写；产品化入口不全）。

### 4. 接口契约

- 调用：`Authorization: Bearer fab-…` 或 `x-api-key: fab-…`
- 过期 / 无效：401 `invalid virtual key`
- 模型不在名单：403 `model not allowed`

### 5. 实现步骤

| 条 | 现网落点 | 状态 |
|----|----------|------|
| fab- 校验 + 哈希解析 | `relay`、`ResolveVK` | Done |
| 两端点同 VK | 无协议字段 | Done |
| 模型范围 | `flag.Model` vs `ModelScope` | Done |
| 过期 | `ExpiresAt` 比较 | Done（管理创建未带 expires 表单） |

### 6. 验收标准

1. 同一把 `fab-` 两个 `/v1` 端点都能用。
2. 非 `fab-` 或伪造钥匙 → 401，且不泄露上游 Secret。
3. 模型不在白名单 → 403。
4. `expires_at` 已过 → 401。
