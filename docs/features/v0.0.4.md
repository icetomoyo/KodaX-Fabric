## FEATURE_004: 同协议多渠 failover

> **状态**：**Completed**（按现网能力，不是愿景全表）  
> **版本**：v0.0.4 → Released v0.1.0

### 1. 需求概述

#### Problem Statement

一条上游挂了，同一协议还应有备路。调用方写错（400）不能拿去狂打备路。

#### Solution

`ChannelsForProtocol` 过滤协议与 active，排序后 `relay` 依次 `proxy`。`retryable`：建连失败或上游 ≥500。成功 2xx/3xx 记账后返回。4xx 透传并停止。

#### Out of Scope

- 跨协议、改 model 名、ROI 选路（#36 #37 #41）
- 路由审计表

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 数据 | `channels.priority`、`weight`、`status` |
| 热路径 | `store.ChannelsForProtocol` + `hub.relay` 循环 |
| 管理 | `POST /api/v1/channels`、`POST /api/v1/channels/{id}` |

### 3. 技术方案

- 协议取值：`openai_chat` / `anthropic_messages`。
- 熔断开路的渠本轮跳过（与 0.0.6 衔接）。
- 全员试完仍失败：网络类 502，全熔断 503。

### 4. 接口契约

管理创建渠：`pool_id, provider_key_id, protocol, base_url, status, priority, weight`。  
调用方契约不变；失败时可能换渠，body 仍是第一次成功或最后一次不可重试的上游响应。

### 5. 实现步骤

| 条 | 现网落点 | 状态 |
|----|----------|------|
| 排序候选 | `ChannelsForProtocol` | Done |
| 5xx 换路、4xx 停 | `proxy.retryable` | Done |
| 禁跨协议 | 按 path 协议过滤 | Done |

### 6. 验收标准

1. 同协议两条渠，主路 500，请求落到备路。
2. 上游 400 不换渠。
3. 池内无该协议渠 → 503，不改打另一协议。
4. 不验收加权抽签、改模型名、审计页。
