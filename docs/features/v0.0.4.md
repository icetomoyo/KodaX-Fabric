### 1. 需求概述

#### Problem Statement

开发者只点模型名，不该自己选 Azure 东还是直连。002 能在同协议多把 Key 上轮转，但分不出主备、不能按权重摊、主路 5xx 不会换备路，出了问题也无法回放「为什么走了这条」。400 若跟着重试，会把调用方自己的错请求再打一遍。

#### Solution

渠 = 协议 + 官方 Key + 可服务模型名单 + 权重 + 优先级。同一协议、能提供该模型的多条渠组成一路：先走 priority=1，全挂再走更大编号的备路；同级按权重做确定性轮转。上游 429 / 5xx / 网络错误：同协议、同模型换下一渠再试（首次后再试最多 2 次）。4xx 不换、不重试。主模型整池不可用时，可按别名落到同协议备用模型（仅此时改发出去的 `model`）。每次响应带路由摘要头，并留下可回放的选路记录。禁止跨协议。vLLM / 其他 OpenAI 兼容上游就是一条 `openai_chat` 渠。

#### Out of Scope

- 跨协议 Fallback（GPT→Claude）
- 延迟优先、成本优先、ROI 选路、排队、降级（#36 #37 #41 #44 #45）
- VK 绑项目/团队、池分组产品化（0.0.5）
- 限流熔断半开（0.0.6）
- 管理后台必须能配 priority/weight/别名（T1 不测操作台）
- Token ROI / Commerce / SSO

### 3. 技术方案

**D1 渠的形状**  
Channel = 协议 + Provider Key + 模型名单 + weight + priority。名单空 = 该协议下不限模型（仍受 VK `model_scope` 约束）。名单非空 = 只有请求模型（或别名展开后的当前模型）在名单内才入候选。vLLM 等兼容上游 = 一条 `openai_chat` 渠。

**D2 优先级主备**  
`priority=1` 是主路；数值越大越备。0 或未设排在所有显式正优先级之后，避免旧默认压过主备。先耗尽当前优先级的健康候选，再降到下一档。

**D3 同级权重**  
同优先级按权重做**确定性**轮转（PRD「加权轮转」，T1 可证明 3:1），不是每次随机抽签。轮转键 = VK + 协议 + **当前请求模型名**，避免不同模型抢同一指针。weight≤0 视为 1。

**D4 换渠重试**  
一次调用：第一次选路之后，若该次上游是 429、5xx 或网络错误，换一条尚未试过的同协议同模型渠再打，最多再试 2 次（合计最多 3 条渠）。4xx（含 400/401/403）立刻停，不换渠。002：官方 Key 的 401/403 仍停用该 Key，但**当次**不因此改打另一条。退避可配；T1 用零等待或注入时钟，测例不睡墙钟。

**D5 同协议模型 Fallback**  
主模型在本协议已无健康候选（或换渠用尽）时，若别名配置了同协议备用模型名，把发出去的 JSON `model` 改成备用名再走 D2–D4。只改 `model` 字段，其余 body 仍零转换。没有别名或备用也不可用 → 该端点 503，**不得**改打另一协议。

**D6 别名**  
一个客户端模型名 → 本协议下的主模型名 + 可选 fallback 模型名。未配置别名时，请求里的 `model` 就是主模型名。别名不跨协议。

**D7 审计**  
每次响应带 `x-fabric-request-id` 与路由摘要头（选了哪条渠、reason、是否 Fallback）。reason：`priority` | `weighted` | `failover` | `model_fallback`。Fallback=true 表示发生过换渠或换模型。单渠网络失败且未换路：记下原选路且 Fallback=false。选路记录持久化；**写失败不影响**把上游结果回给调用方。

**D8 003 之前的闸**  
鉴权 → 过期 → VK 模型名单 → 本版选路。名单拦截仍不推进轮转、不打上游。

### 4. 接口契约

调用方路径与鉴权与 001–003 相同。

| 条件 | 行为 |
|------|------|
| 主路 5xx/429/网络错误，同协议有备路 | 换渠再打；最终成功则回备路响应 |
| 上游 400 等 4xx | 透传该次状态/body，不再打第二条 |
| 同级 weight 3 与 1 | 连续健康请求命中比例可证明约 3:1 |
| 别名 fallback | 主模型全挂后，发出去的 `model` 为备用名；调用方仍按原协议收响应 |
| 仅有另一协议的活渠 | 本端点 503，0 次打到另一协议 |
| 成功或最终失败 | 都带路由摘要头 |

- 官方 Key 明文仍不得出现在调用方响应。  
- 除模型 Fallback 时的 `model` 外，请求体不改。

### 6. 验收标准

#### User Stories

1. 作为开发者，主路 5xx 时我的同模型请求会打到备路并成功，以便我不自己选厂商。  
2. 作为开发者，我写错请求得 400 时网关不会再打第二条，以免重复扣费。  
3. 作为平台，同优先级两条渠按权重分流，连续打流能看出 3:1 这类比例，以便摊限流。  
4. 作为平台，我能从响应头（及持久记录）回放选了谁、为什么、有没有 Fallback。  
5. 作为开发者，主模型整池不可用时，可落到配置的同协议备用模型，请求格式不用变。  
6. 作为开发者，OpenAI 侧全挂时 Chat Completions 不会改走 Anthropic，以免协议错乱。  
7. 作为平台，我可以把 vLLM 等兼容上游挂成一条 OpenAI 渠，调用方仍只改 Base URL。
