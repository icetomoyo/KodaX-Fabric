## FEATURE_004: 同协议多渠 failover

> **状态**：**Completed**  
> **Spec**：已综合（T1）  
> **Tickets / Implement**：#1–#5 **Done**  
> **版本**：v0.0.4 → Released v0.0.4

### 1. 需求概述

主路 5xx 走备路；400 不重试；同优先级按权重；审计头能回放选了谁、为什么、有没有 fallback。

### 2. 影响范围

渠增加 priority / weight / models；`model_aliases`；热路径一次请求最多 2 次上游尝试。

### 3. 技术方案

- Channel = 协议 + Key + 模型列表 + 权重 + 优先级（#25/#26）。
- **priority=1 主路，数值越大越备**；0/未设排在显式 1/2 之后，避免旧默认压过主备。
- 同级按权重轮转，RR key = vk+protocol+requested model（#33/#34/#40）。
- 429/5xx/网络错误可换同协议下一渠：首次后再重试最多 2 次（最多 3 渠）；4xx 停（#39）。
- 别名 targets 第一项主模型，后续同协议 fallback，仅此时改 body 的 `model`（#32/#35）。
- 审计：响应头 + 持久 `RouteDecision`。`Fallback=true` 表示发生过换渠或换模型。单渠网络失败记原选路 reason 且 Fallback=false。写失败不影响主请求（#38）。
- 禁止跨协议。

### 4. 接口契约

调用方路径不变。成功或最终失败响应带审计头。`reason`：`priority` | `weighted` | `failover` | `model_fallback`。
