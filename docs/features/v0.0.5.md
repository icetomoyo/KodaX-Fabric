## FEATURE_005: VK 绑池与分组

> **状态**：**Completed**（无组织树，隔离靠不同池）  
> **版本**：v0.0.5 → Released v0.1.0

### 1. 需求概述

#### Problem Statement

两把员工钥匙不该打到同一摊官方 Key，除非管理员故意把它们挂进同一个池。

#### Solution

创建 VK / 申请 VK 都指定 `pool_id`。热路径只解析该池渠。池用 `group_name` 标记档位，不做运行时再映射。

#### Out of Scope

- 项目、团队、组织树
- 运行时按任务改池

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 数据 | `channel_pools.group_name`、`virtual_keys.pool_id` |
| API | `GET/POST /api/v1/pools`；创建 VK / 申请带 `pool_id` |
| UI | 管理员建池；开发者申请时选池 |

### 3. 技术方案

- 隔离边界 = 池。官方 Key 经 Channel 挂进某个池，另一个池看不见。
- 角色仍是 `admin` / `developer`。

### 4. 接口契约

`POST /api/v1/pools`：`{ "name", "group_name" }`。  
`POST /api/v1/virtual-keys` 与 `POST /api/v1/me/vk-applications` 必须带 `pool_id`。

### 5. 实现步骤

| 条 | 现网落点 | 状态 |
|----|----------|------|
| 池 + group | `CreatePool` | Done |
| VK 外键池 | `CreateVK` / `CreateApplication` | Done |
| 解析按池 | `ResolveVK` WHERE `c.pool_id` | Done |

### 6. 验收标准

1. 两把 VK 挂不同池，A 打不到 B 池的官方 Key。
2. 池可标 premium / standard / bulk。
3. 不验收项目/团队树。
