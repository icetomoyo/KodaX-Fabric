## FEATURE_005: VK 绑池与分组

> **状态**：**Completed**  
> **Spec**：已综合（T1）  
> **版本**：v0.0.5 → Released v0.0.5

### 1. 需求概述

两把 VK 走不同池；A 团队打不到 B 的官方 Key；分组可从解析/审计证明。

### 2. 影响范围

PG：`teams` / `projects`；池与官方 Key 带 `team_id`；VK 带 `project_id`。Memory：`IsolateChannels`。审计记 TeamID/PoolID/PoolGroup。

### 3. 技术方案

- 链路从 VK 解析，不读调用方 team/pool 头。
- 查询：渠的 pool_id = VK.pool_id，且 pool.team_id = project.team_id = key.team_id。
- 无归属 VK 只能打无归属 pool+key；有团队则 pool.team_id == project.team_id == key.team_id，且渠 pool_id 必须等于 VK.pool_id（0 不是通配）。
- 0.0.1–0.0.4 夹具：TeamID=0 且渠 TeamID/KeyTeamID=0。
- group_name：premium / standard / bulk。

### 4. 接口契约

调用方路径不变。响应可带 `X-Fabric-Pool-Group` / `X-Fabric-Team-Id`。审计含团队与分组。

### 5. 实现步骤

#1 两 VK 不同池 · #2 跨团队 Key 被滤掉 · #3 三分组可审计。均 Done。

### 6. 验收标准

`TestTwoVKsDifferentPools`、`TestTeamACannotUseTeamBKey`、`TestPoolGroupsVisibleInAudit`、`TestIsolateChannelsDropsForeignTeamKey`。
