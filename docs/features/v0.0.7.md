### 1. 需求概述

#### Problem Statement

一把 VK 没有月度上限时，长对话或写坏循环会一直烧到厂家账单。006 只刹 RPM，不刹「这个月已经用了多少」。流式回答还在喷的时候，也看不到用量在涨，等全部结束才知道超没超，往往已经超了。

#### Solution

VK 带 **本月 Token 预算**（软 80% / 硬 100%）。请求开始前：已用 ≥ 硬限额 → **402** `budget_exceeded`，0 次上游；已用 ≥ 软限额但仍低于硬限额 → 放行并提醒。流式过程中用简易规则估已输出量，调用方能看见用量在涨；结束后优先用厂家 `usage` 校准入账，没有 usage 才用估算。预算按 VK 隔离，按自然月（可拨时钟）清零。未配预算的旧夹具不限。

#### Out of Scope

- ¥ 计价 / Pricebook / Credits / 利润（Commerce）
- 组织瀑布账：项目 → 团队 → 企业（本版只做 **VK**）
- 预算预占、中途掐流
- 软限制时自动降级换便宜模型
- team/project 维限流补全、缓存、审批、IP 白名单（0.0.8）
- 登录页、完整预算管理后台
- Token ROI

### 3. 技术方案

**D1 先查再打**  
已用 Token ≥ 硬限额 → 402，假上游命中 0。另一把 VK 账本独立。未配限额视为无限。

**D2 软提醒**  
已用 / 限额 ≥ 80% 且未到硬限：请求仍 200，响应带提醒（如 `X-Fabric-Budget-Warn: true` 与用量摘要）。不降级换模型。

**D3 入账**  
非流：解析厂家 JSON `usage`（OpenAI `total_tokens` 或 prompt+completion；Anthropic 同类字段）累加到该 VK 本月已用。流式：过程中按输出增量估算；结束后若有 `usage` 则用厂家数校准（估算被覆盖），无 usage 则用估算并视为已入账。

**D4 流式可见**  
不改写厂家事件体。T1 可在 SSE 流里看到用量递增的注释行。手测「长流过程中用量在涨」指这条旁路，不是改 `choices`。

**D5 不中途掐**  
已经放出的流不因估算超标而掐断。硬闸只在 **下一请求开始前**。

**D6 自然月**  
账本按 `Now` 的年-月分桶。拨到下月，旧月已用不挡住新月请求。

### 4. 接口契约

调用方路径不变：`POST /v1/chat/completions`、`POST /v1/messages`，鉴权仍是 `fab-`。

| 条件 | 行为 |
|------|------|
| 未配月限额 | 与 0.0.6 相同，不 402、无预算头 |
| 已用 < 80% | 200，上游照打 |
| 80% ≤ 已用 < 100% | 200，带预算提醒；上游仍打 |
| 已用 ≥ 100% | 402，`code=budget_exceeded`；该 VK 上游命中 0 |
| 另一把未超的 VK | 仍 200 |
| 非流且厂家带回 usage | 入账数 = 厂家 usage，不是估算 |
| 长流 | 流里能看见用量数字变大；结束后以 usage 校准 |
| 拨到下月 | 上月已用不再硬拒 |

官方 Key 明文仍不得出现在调用方响应。402 不泄露内部账本实现。

### 6. 验收标准

#### User Stories

1. 作为平台，VK 到月额度要硬拒，以免一张卡刷穿。  
2. 作为开发者，快到额时我能看见提醒，但请求还能打出去。  
3. 作为开发者，长流的时候能感到用量在涨，不用等全部结束。  
4. 作为平台，入账以厂家 `usage` 为准，估算只是过程中的预览。  
5. 作为开发者，我的 VK 不该被别人的预算牵连。  
6. 作为平台，新的一个月从零开始算。  
7. 作为开发者，没配预算的旧钥匙行为不变。

#### Testing Decisions

**缝 T1（已确认，2026-08-13 用户确认「是」）**：进程内 `POST /v1/chat/completions`（非流 + `stream:true`）。Messages 抽一条覆盖硬拒即可。

夹具：VK 月限额、已用量、可拨 Now。假上游回带固定 `usage` 的 JSON，或一段一段 SSE。

测外部行为：

- 已用 ≥ 限额 → 402，上游 0 命中。  
- 已用在软区间 → 200 + 提醒头，上游 1 次。  
- 另一把 VK 不受牵连。  
- 非流成功后，下一枪的硬拒阈值按厂家 usage 累加（不是估算）。  
- 长流 SSE 中用量数字递增；结束后以 usage 入账。  
- 拨到下月，上月打满的 VK 又能 200。  
- 未配预算的 001–006 测例仍绿。
