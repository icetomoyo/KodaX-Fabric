## FEATURE_007: VK 月 Token 硬预算

> **状态**：**Completed**（硬闸 + 非流式 usage；无软闸、无边流边估）  
> **版本**：v0.0.7 → Released v0.1.0

### 1. 需求概述

#### Problem Statement

一把钥匙一个月不能无限烧。到额应拦住，而不是只记一笔账。

#### Solution

解析时若 `usage_month` 不是当前 UTC 月则 used 归零。`MonthlyTokenLimit>0` 且 used ≥ limit → 402。非流式 2xx 后把 `total_tokens`（或 prompt+completion / input+output）写入 used。

#### Out of Scope

- 软提醒、金额预算、流式中估算、tiktoken

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 数据 | `virtual_keys` 三月度字段 |
| 热路径 | `relay` 预算检查；`AddUsage` |
| 管理 | 创建 VK 可带 `monthly_token_limit` |

### 3. 技术方案

- 402 envelope：`budget_exceeded` / `insufficient_quota`。
- 流式成功不记账（现网缺口，验收不要求边流边涨）。

### 4. 接口契约

超预算：402。创建 VK：`monthly_token_limit`（0 = 不限）。

### 5. 实现步骤

| 条 | 现网落点 | 状态 |
|----|----------|------|
| 硬拒 | `writeBudgetExceeded` | Done |
| 非流式累加 | `parseUsageTokens` + `AddUsage` | Done |
| 换月清零 | `ResolveVK` | Done |

### 6. 验收标准

1. 到月额度后新请求 402，不打上游。
2. 非流式成功后 used 增加，增量来自响应 `usage`。
3. 不验收软提醒、流式过程中 used 上涨。
