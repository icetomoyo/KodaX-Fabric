### 1. 需求概述

#### Problem Statement

三个角色都进 `/admin`，顶栏能看见自己的名字，但不能改。改显示名和密码的接口其实已经有了；旧工作台表单也在，只是 0.1.2 撤掉 `/app` 之后没人进得去。想换显示名或改密，只能找管理员在「用户」里改，开发者连那个页都进不去。

#### Solution

在共用 `/admin` 壳里给每个登录者一页「我的资料」：看见自己的手机号（只读）、改显示名、改登录密码。保存走现有 `PATCH /console/v1/me`，只动自己。顶栏名字跟着变。改别人仍走用户管理，本页不管。

#### User Stories

1. 作为企业管理员，我想改自己的显示名，以便顶栏和管理员列表显示新名字。
2. 作为团队管理员，我想改自己的登录密码，以便用新密码重新登录，旧密码立刻失效。
3. 作为开发者，我想在 `/admin` 里改自己的显示名和密码，以便不求管理员、也不再依赖已撤掉的工作台。
4. 作为任一角色，我想留空密码只改显示名，以便不会误把密码清掉。
5. 作为任一角色，我不想通过「我的资料」改角色、团队或手机号，以免自己提权或改掉登录账号。
6. 作为开发者，我不想在本页改别人的资料；别人仍只能由有权的管理员在用户管理里改。

#### Out of Scope

- 改别人的资料或密码（`PATCH /console/v1/users/{id}`，本版不扩）
- 自己改 `role` / `team_id` / `phone` / `status`
- 找回密码、邮箱、头像、SSO
- 超管 / 多租户
- 新开一套账号 API

### 3. 技术方案

**D1 不扩 body 形状**  
`PATCH /me` 继续只解码 `name`、`password`。即便客户端带上 `role` / `team_id` / `phone` / `status`，也不得写入。不要改成解码完整 `OperatorUpdate`。

**D2 只改自己**  
目标 id 来自 session，不接受路径或 body 里的别人 id。

**D3 密码规则**  
有值则至少 8 位，否则 400。空字符串或不传 = 不改密。成功后旧密码不能再登录。响应不得带回明文或 `password_hash`。

**D4 入口**  
`/admin` 壳内一页资料，三角色都能进（不是 staff-only）。保存成功后顶栏显示名用已有 me 缓存更新。

**D5 热路径不动**  
选渠、VK、预算与本版无关。

---

### 4. 接口契约

已有，本版锁定行为：

| 方法 | 路径 | 谁 | 行为 |
|------|------|----|------|
| GET | `/console/v1/me` | 已登录 | `{ operator }`，无 hash |
| PATCH | `/console/v1/me` | 已登录 | body `{ name?, password? }` → `{ operator }` |

- `password` 有值且 `< 8` → 400
- 未登录 → 401
- 改密后：新密码登录 200，旧密码 401
- body 夹带 `role` / `team_id` / `phone` / `status` → 这些字段保持原值
