### 1. 需求概述

#### Problem Statement

一把 VK 写坏循环，或同一家官方 Key 打满合同，不该把整组或厂家额度烧穿。现在 004 只会在当次 5xx/429 换路，病路下一秒还可能再被选中。限流没有硬闸，也没有半开，员工只能等上游自己拒绝。

#### Solution

热路径在选渠前先过 **VK、Provider 两维令牌桶**。超限 **硬拒绝 429**，允许短时突发，不排队、不降级换模型。渠用滑动窗口看成功率，病路摘掉；冷却后半开放几枪，成功再接回。流量只在 **同池、同协议、已隔离** 的健康渠之间切。004 的当次 failover 仍在其后；熔断打开的渠不得为了重试再捞回来。

#### Out of Scope

- 四维限流一次做满（team / project 维留给后面）
- 排队、超限降级换便宜模型（#44 #45）
- VK 月预算、流式估 Token / TPM 扣减（0.0.7）
- 定时主动 ping 上游 `/v1/models`（#47 本版用被动检测 + 半开探测）
- 池级 RPM 总闸（避免变成第三维限流）
- 缓存、审批、IP 白名单（0.0.8）
- 登录页、四角色控制台
- Token ROI / Commerce / SSO

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 限流维 | 只做 **VK（per-api-key）** 与 **Provider（provider_code 合同）**。夹具写 RPM；未配限额视为不限 |

### 3. 技术方案

**D1 两维桶，细的先刹**  
先扣 VK RPM，再扣该请求将打到的 Provider。任一耗尽 → 429，`code=rate_limited`，0 次上游。另一把 VK 的桶独立。同一 `provider_code` 下多把官方 Key 共用 Provider 桶。

**D2 突发**  
令牌桶：满额 = ceil(RPM × 1.2)，按 RPM/分钟回填。短时连发先放过，细水长流才 429。

**D3 摘病路**  
只根据 **已经打出去的** 响应做被动检测（5xx / 网络错误算失败；4xx 不算熔断失败）。窗口内错误率超阈值 → 该渠 OPEN，后续 pick 跳过。同池还有健康渠则 004 接上（#30）。

**D4 半开**  
OPEN 满冷却时间 → HALF-OPEN，最多放 N 枪探测。探测成功 → CLOSED；失败 → 回到 OPEN 再冷却。T1 拨时钟，不测后台定时 ping。

**D5 顺序**  
隔离后的候选里再滤 OPEN、再限流、再主备/权重。跨团队 Key、跨协议渠，熔断也不得捞回。

**D6 429 分层**  
Fabric 自己的限流 429：不换渠重试（VK 已尽或该 Provider 已尽且池内无其他 Provider）。上游返回的 429：仍按 004 换同协议备路。

### 4. 接口契约

调用方路径不变：`POST /v1/chat/completions`、`POST /v1/messages`，鉴权仍是 `fab-`。

| 条件 | 行为 |
|------|------|
| VK RPM 打满（含突发用尽） | 立刻 429；该 VK 的假上游命中 0 |
| 另一把 VK 未超 | 仍 200，互不牵连 |
| 同一 Provider 合同 RPM 打满 | 打该厂家的渠全部跳过；池内仅剩这家则 429 |
| 主路连续失败触发 OPEN | 后续请求 0 次再打该渠；同池备路承接 |
| 冷却后半开 | 允许再打该渠有限次数；成功则恢复，失败再摘 |
| 未配 RPM / 未达阈值 | 与 0.0.5 行为一致 |

官方 Key 明文仍不得出现在调用方响应。限流 429 不泄露桶实现细节。

### 6. 验收标准

#### User Stories

1. 作为平台，VK 超 RPM 要立刻 429，以免一把钥匙打穿厂家。  
2. 作为平台，短时连发可以先过（突发桶），细水长流超了再刹。  
3. 作为平台，同一厂家多把官方 Key 共用合同上限，打满整家都刹。  
4. 作为开发者，我的 VK 不该被别人的 VK 限流牵连。  
5. 作为平台，连续失败的渠要摘掉，流量留在同池健康路上。  
6. 作为平台，摘掉的渠过一会儿半开试探，好了再接回来。  
7. 作为开发者，001–005 没配限额时行为不变。

#### Testing Decisions

**缝 T1（已确认，2026-08-13 用户确认「是」）**：进程内 `POST /v1/chat/completions`（Messages 抽一条覆盖即可）。

夹具：VK RPM、Provider RPM、双渠（一病一活）、可拨时钟。假上游按次数回 200 或 5xx。

测外部行为：

- 超 VK RPM → 429，上游命中停在限额内。  
- 突发允许略超再刹（与 1.2 倍一致的整次数）。  
- 另一把 VK 仍通。  
- Provider 桶尽 → 该厂家上游 0 命中。  
- 主路连续 5xx 后不再被选，备路接上。  
- 拨过冷却后主路再被打（半开）；再失败则又不再打。  
- 未配 RPM 的旧形状测例仍绿。

**不测**：Redis、读库、登录页、主动 ping、排队/降级、TPM/预算。
