## FEATURE_006: RPM 硬拒绝与渠熔断

> **状态**：**Completed**（两维硬拒绝，不是 HLD 四维 Redis）  
> **版本**：v0.0.6 → Released v0.1.0

### 1. 需求概述

#### Problem Statement

一把钥匙写坏循环不能打穿上游。一条病路不能继续砸请求。

#### Solution

`Limiter.AllowRPM`：`rpm_limit>0` 且本分钟次数用尽 → 429。`RecordFailure` 两次后 `openUntil=now+15s`；`ChannelOpen` 为假则跳过。成功 `RecordSuccess` 清状态。

#### Out of Scope

- Redis Lua、四维限流、排队、降级、主动探活

### 2. 影响范围

| 区域 | 决策 |
|------|------|
| 热路径 | `internal/hub/limits.go`、`relay` |
| 数据 | `virtual_keys.rpm_limit`（0 = 不限） |
| 状态 | 进程内存；重启丢失 |

### 3. 技术方案

- 429 envelope 跟协议。
- 熔断与 failover 组合：开路跳过，试下一条。
- `rpm_limit=0` 放行。

### 4. 接口契约

超 RPM：429 `rate_limit_exceeded` / Anthropic `rate_limit_error`。  
全熔断：503 `circuit_open`。

### 5. 实现步骤

| 条 | 现网落点 | 状态 |
|----|----------|------|
| VK RPM | `AllowRPM` | Done |
| 熔断 2 次 / 15s | `RecordFailure` / `ChannelOpen` | Done |
| 测例 | `internal/hub/server_test.go` | Done |

### 6. 验收标准

1. 设了 RPM 的 VK 超限立刻 429。
2. 一条渠连失败后 15s 内不再打它。
3. 池内匹配渠全开路 → 503。
4. 不验收 Redis 共享计数、四维限流、主动探测。
