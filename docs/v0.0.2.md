# TokenHub v0.0.2 变更说明

| 项 | 内容 |
|---|---|
| 版本 | `v0.0.2` |
| 基线 | `4148fa0`：`feat: update version to 0.0.1 and refactor layouts for employee workspace` |
| 变更范围 | 基线之后至当前 `HEAD` 的功能、工程和安全变更 |
| 当前状态 | 功能已在代码中实现；`package.json` 版本号是否正式升级，待发布时确定 |

本文只记录 v0.0.1 基线之后的增量。v0.0.1 已覆盖的员工 API Key 渠道硬绑定、协议代理、模型发现、渠道内调度与重试、Responses 亲和、角色隔离和基础审计契约不在本文重复展开。

## 1. 版本目标

v0.0.2 聚焦管理端可运维性、上游渠道配置可解释性、账号体验、数据隐私和部署便利性：

1. 统一供应商与模型产品线的展示名称，降低管理员在渠道、日志和 Key 页面之间切换时的认知成本。
2. 将产品线的协议路由、上游地址和鉴权方式配置显式化，并提供配置版本、连接测试和变更风险提示。
3. 完善个人中心的基本信息和密码修改体验。
4. 收紧员工 API Key 的可见边界，管理员员工列表不再返回任何 Key 信息。
5. 从 pnpm workspace 迁移到 npm workspace，并支持在局域网内访问开发环境。

## 2. 功能变更

### 2.1 公司 / 模型渠道命名

供应商模板从单一展示名称拆分为公司名称和模型品牌名称，并统一组合成：

```text
公司名称/模型名称
```

示例：

| 公司 | 模型 | 展示名 |
|---|---|---|
| 智谱 | GLM | 智谱/GLM |
| 月之暗面 | Kimi | 月之暗面/Kimi |
| 深度求索 | DeepSeek | 深度求索/DeepSeek |

规则：

- `provider.name` 保存公司名称；`product_lines.name` 保存模型或区域产品线名称。
- 已存在的模板渠道在快速创建或批量导入时会按模板同步漂移的展示名称。
- 渠道列表、渠道详情、批量导入、Key 创建结果、管理概览、调用日志和员工 Key 页面统一使用该格式。
- 同一公司下不同区域仍然是独立渠道，例如 `月之暗面/Kimi（中国区）` 与 `月之暗面/Kimi（国际区）`。

### 2.2 产品线协议路由配置

产品线不再只依赖一个隐含的公共地址和鉴权方式，而是可以按协议保存路由配置：

```json
{
  "openai_chat": {
    "baseUrl": "https://example.invalid/v1",
    "authStyle": "bearer"
  },
  "anthropic_messages": {
    "baseUrl": "https://example.invalid",
    "authStyle": "x-api-key"
  }
}
```

支持的管理能力：

- 在渠道编辑中选择支持协议，并分别查看每个协议的上游 URL 和鉴权方式。
- 使用 `ChannelConfigFields` 编辑渠道名称、协议集合和状态。
- 使用 `ProtocolRouteSummary` 在渠道列表、Key 详情和导入确认界面展示协议路由。
- 通过 `configVersion` 做乐观并发控制；配置已被其他操作更新时返回 `CHANNEL_CONFIG_STALE`，要求刷新后重试。
- 修改协议或协议路由后清理凭证的旧连接测试结果和发现模型，避免继续使用过期健康信息。
- 移除协议前检查仍在使用该协议的 active 员工 Key；存在有效绑定时返回 `PROTOCOL_IN_USE`，不允许保存。
- 管理员可按指定协议发起连接测试；HTTP 200 但响应体表示业务失败时，也会被识别为测试失败。
- 旧版固定 URL / 鉴权配置会在界面中标记为旧配置；只有明确应用协议路由升级后才切换，避免普通字段保存造成隐式路由变化。

接口边界：

| 接口 | 作用 | 权限 |
|---|---|---|
| `GET /api/admin/providers` | 查看供应商及其产品线 | admin |
| `GET /api/admin/product-lines` | 查看产品线协议配置和配置版本 | admin |
| `PATCH /api/admin/product-lines/:id` | 修改名称、状态、协议及协议路由 | admin |
| `POST /api/admin/credentials/:id/test` | 按协议测试上游连接 | admin |

### 2.3 个人中心与密码体验

`/admin/profile` 的个人中心完成分区重构：

- 基本信息区：姓名、手机号、部门；手机号同时作为登录标识。
- 角色只读展示，不能在个人中心修改。
- 修改密码区统一提供原密码、新密码和确认密码，并支持显示 / 隐藏密码。
- 表单在保存前校验必填项、手机号长度和两次密码一致性；保存成功后清空密码输入并刷新当前用户信息。
- 基本信息支持“保存个人信息”和“取消修改”，未发生变化时保存按钮禁用。

### 2.4 员工 API Key 隐私收口

v0.0.2 对历史上曾经存在的 Key 读取能力进行收口，当前规则为：

- 加密存储仍使用用途隔离的员工 Key 加密目的，但服务端移除员工 Key 解密函数。
- 员工 Key 明文只在创建成功响应中向创建者展示一次；员工侧不提供 reveal 接口。
- 管理员侧不提供员工 Key 列表和 reveal 接口，管理员不能查看、复制或代员工创建 Key。
- `GET /api/admin/users` 不返回 `activeApiKeyCount`、Key 名称、前缀、协议、绑定渠道或明文。
- 员工管理页面只展示员工账号字段：姓名、手机号、部门、状态和最近登录；`id / role / status` 仅作为编辑和启停操作所需的内部数据。
- 状态使用标签展示：正常为成功色，已停用为危险色；部门列宽扩大到 240px 以容纳较长部门名称。
- 新增管理员路由安全测试，确保 Key 列表和 reveal 路由不会重新注册。

员工本人仍可通过 `/api/me/api-keys` 查看自己的摘要并删除自己的 Key；删除会写操作审计，删除后的 Key 立即失效。

### 2.5 npm workspace 工程化

项目从 pnpm workspace 切换到 npm workspace：

- 根目录声明 `server` 和 `web` 两个 npm workspace。
- 新增 `package-lock.json`，移除 `pnpm-lock.yaml` 和 `pnpm-workspace.yaml`。
- 根脚本统一使用 npm workspace 调用：

```sh
npm install
npm run dev
npm run dev:server
npm run dev:web
npm run build
npm run db:setup
npm run test:server
```

- 新增 `scripts/dev.mjs`，并行启动 server 和 web；任一子进程退出或收到终止信号时，会清理另一子进程。
- 集成测试中的运行命令同步改为 npm workspace 形式。
- Node.js 要求收紧为 `^20.17.0 || >=22.9.0`，npm 要求为 11.x。

### 2.6 局域网开发访问

开发服务默认监听所有网卡：

- API 默认 `HOST=0.0.0.0`、端口 `3100`。
- Vite 默认监听 `0.0.0.0`、端口 `5173`。
- Vite 的 `/api`、`/health` 和 `/v1` 代理开启 `xfwd`，便于服务端获取转发后的请求信息。
- 同一局域网内其他设备可以通过宿主机局域网 IP 访问 Web 和 API，例如：

```text
http://<局域网 IP>:5173
http://<局域网 IP>:3100
```

部署或内网使用时仍需显式配置 `CORS_ORIGIN`，并在操作系统防火墙中允许 Node.js 监听端口；监听所有网卡会扩大服务暴露范围，不应直接暴露到不可信网络。

## 3. 数据库与兼容性

### 3.1 产品线协议配置字段

v0.0.2 增加产品线配置字段：

| 字段 | 类型 | 用途 |
|---|---|---|
| `product_lines.protocol_configs` | `jsonb` | 保存各协议的 URL 与鉴权方式 |
| `product_lines.config_version` | `integer` | 乐观并发控制和配置变更版本 |

对应迁移为 `server/drizzle/0001_youthful_mercury.sql`。部署前执行标准迁移流程：

```sh
npm run db:migrate
```

### 3.2 旧协议配置兼容

- `protocol_configs` 为空时，运行时继续使用历史 `base_url_override`、供应商默认 URL 和旧鉴权方式作为回退。
- 新渠道优先生成按协议配置；已有渠道不会在没有明确操作时隐式升级。
- 渠道协议发生变化会增加 `config_version`，并使凭证健康检查重新开始。
- 并发编辑收到 `CHANNEL_CONFIG_STALE` 后，应重新拉取产品线再提交。

### 3.3 接口兼容变化

- 管理员员工 Key 列表和 reveal 接口已移除；调用这些旧接口的客户端需要改为员工本人 `/api/me/api-keys` 摘要接口，不能绕过权限读取明文。
- `activeApiKeyCount` 不再是管理员员工列表响应字段。
- 供应商和产品线的展示名可能在模板快速创建或批量导入时被规范化为“公司/模型”。
- 原 pnpm 命令不再作为项目标准入口，使用 npm workspace 命令。
